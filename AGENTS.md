# NeoHome — agent notes

Spec authority is `PROJECT.md` (verbatim user spec). `WORKSTREAM_NOTES.md` + `git log --oneline -15` show active workstream file ownership — check before touching cross-cutting files.

## Hard constraint (from spec)

Never execute host code: no real ELF/PE, no player input passed to host shell, no real Docker/VM per player. Everything is Go state in `internal/core` driven by builtins in `internal/shell`. Every new command/service must read or write real world state (no stub "installed successfully"), every anomaly needs a traceable cause, no wait-walls.

## Layout

- `cmd/neohome/` — real entry: telnet `:2024` + SSH `:2222`, `NEOHOME_WORLD` (default `world.gob`), engine ticks every 3s, saves every 12th tick.
- `internal/core/` — world state machine (`World`, `Device`, VFS, `Tick()` in `engine.go`, gob `Save`/`Load` in `resolver.go`, seed in `world_init.go`).
- `internal/shell/` — virtual shell builtins (`NewShell` + `ExecLine` + `RunLoop` in `shell.go`).
- `tests/` — the only package with tests. `tools/` — live end-to-end verify scripts + drivers (`live_drive.go`, `sshdrive/`).

Import direction is one-way: `shell` imports `core`; **`core` must never import `shell`** (cycle). Cross-layer hooks use registration, e.g. `core.SetCronExec` (see `internal/core/cron.go:32`) satisfied by `shell` init.

## Commands

```bash
go build -o neohome ./cmd/neohome
go vet ./...
go test ./...                                    # only neohome/tests has tests
go test ./tests -run TestName -v                 # single test, e.g. -run TestTmuxSessionsAreRealProcesses
```

Fast unit path (no server): `core.NewWorld()` + `shell.NewShell(w, dev, user, out, ip, tty)` + `ExecLine` — see the `run()` helper in `tests/world_test.go:19`, and `runWithStdin` (same file) when the command reads passwords or an interactive body from stdin.

## Adding a subsystem (pattern)

1. State slot: add a pointer on `World` in `internal/core/world.go` (shape owned by one file, see comment at `world.go:61`).
2. Tick: implement `W.XTick()`, call it from `World.Tick()` in `internal/core/engine.go:190`.
3. Seed: wire initial state in `NewWorld()` (`world_init.go`), daemons/jobs must be world-visible files/services, not hidden maps.
4. Shell: add builtin in `internal/shell/<area>_cmds.go` operating on that state.
5. Test in `tests/<area>_test.go` via `Tick()` advancement (no wall-clock sleeps) + a `tools/<area>_verify.sh` for the live path if entry/networking is touched.
6. Persistence: `World.mu` is unexported so gob skips it — keep new fields gob-encodable (no channels/funcs in persisted structs).

Locking: live server shares one `*World`; hold `w.Lock()` around `Tick`/`Save`/session setup (see `cmd/neohome/main.go`, `ssh.go`).

## Gotchas

- `tools/*_verify.sh` each locate their own checkout (`ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"`) and pick the Go toolchain that exists (`/workspace/go` if present, else `$HOME/.local/tools/go`), so they run from any clone — a new script must copy that header. `all_verify.sh` chains all 18 scripts (its `suspicious` count subtracts the deliberate refusals: `security_verify`'s opening `command not found` twice, and `ssh_verify`'s wrong password) and reports a `suspicious` count per script; review any non-zero (expected-error patterns — the scripted DNS fault's own dnsmasq log is legitimately "suspicious" in `live_verify`, and `ftp_verify.sh`'s closing `Connection timed out (filtered)` is the neighbour hardening, also expected). `killsrv.sh` kills by process-name pattern (`neohome`/`nh_*`); scripts that drive the world from a non-repo cwd must build `./tools/sshdrive` to a binary first (`go run` inside another directory cannot find the module).
- Household LAN numbers have ONE owner: `internal/core/addr.go` (`LANSubnet`, `LANGateway`, the DHCP band constants, `lanIP()`, `AllocLANStatic()` for runtime provisioning such as MCP, `ValidateLAN()` which runs at boot and panics on duplicates/pool-collisions). Never write a `10.77.1.x` literal anywhere else — a wrong seed fails loudly at `NewWorld`, in every test.
- `ftp` (client) is a `internal/shell` builtin, deliberately NOT a busybox applet: do not add it to `bbApplets` or `tests/testdata/busybox/APPLETS.txt`. The FTP *daemon* reads its own `/etc/vsftpd.conf` on every call (`core.FTPConfOf`) — never cache a parsed config; a player who edits the file must see the change on the next command. `listen_port` is intentionally unparsed (the service record's port is the one owner of that fact). The seeded `198.51.100.0/24` numbers live with the rest of the WAN plan in `internal/core/world_init.go` (`mara`'s forward, `darkden`), and only the `ftp` test asserts the drop box's `anon_root=/` vulnerability — keep it that way (fixing the seed would delete the storyline).
- Ignored outputs: `/neohome` binary, `world.gob`/`*.gob`, `tools/_*.sh` scratch (see `.gitignore`) — never commit these.
- `ssh`/`telnet` share one helper (`openRemoteSession` in `internal/shell/remote.go`): with a command it runs it on the target and returns the status, without one it hands over a nested shell using the *same* `bufio.Reader` (never wrap it again — the outer reader's buffer would starve the inner one). A session with no input stream must not enter the nested loop; that used to panic on `bufio.NewReader(nil)`.
- Trust that names a player must be evaluated against the *acting* device, not any device in the world: `core.AssistantKeyTrusted(src, dst)` takes both ends for that reason. The assistant node is key-only (`PasswordAuthentication no`, written by `SeedAssistantAccess`) because that is the directive `remote.go` actually enforces.
- IRC is a network service like the BBS: `internal/shell/irc_cmds.go` resolves `irc.neohome.example` and dials 6667 before touching `World.Chat`. Do not read or write chat in a command without passing that gate; do not cache the resolved address.
- Live ports `:2024`/`:2222` may already be bound; entries degrade independently (server stays headless, engine keeps ticking).
- Package trees live in *files* on the host that serves them: repository-relative paths are meaningless without the document root, so write and read them through the serving path (`core.WebRoot` / `ServeFile`; `pkgnet.go`'s `servedPath`). Metadata URLs are built from `Repo.URL` (the tree root), never from a source line's URL — a source line may name a subdirectory (OpenWrt feeds, Arch sections) or another host (third-party repos).
- `VFS.Read` on a **directory** returns `(nil, true)`: check `IsDir` before `Read` when scanning a directory (`SourcesForDevice` learned this the hard way). `MkdirAll` given a relative path used to loop forever on `path.Dir(".")` — it now bails at the root, and every caller passes an absolute path.
- Mirror state is derived, never assigned by hand: `MirrorTick` (called from `World.Tick`) recomputes `Repo.Status` from the bytes the mirror serves (`World.RepoIntegrity`) plus sync age. Only `StartMirrorSync`, the sync phases and `markStaleDebianTree` set state directly.
- The mirror's own crontab runs `mirror-sync <tree>` every 15 sim-minutes, and `World.Tick` fires it. A test that drives one sync by hand must stop the mirror's scheduler first (`quietMirrorCron` in `tests/pkgs_test.go`) or it will race the repair; `killSyncProc` matches the tree's args for the same reason.
- `Device.InstalledFrom` is per-device package provenance, written when the installing repository is known (`InstallFromView`/`InstallRendered`) and otherwise resolved from that device's *own* sources (`RepoForDevice`), never from a catalogue-wide name match.
- `w.Repos["main"]`/`["contrib"]` are gone: the catalogue is `debian`, `ubuntu`, `alpine`, `arch`, `fedora`, `openwrt`, `sashimi`. `vps create PLAN [hostname] [image]` takes the image (`ProvisionVPSWithOS`); a VPS ships root locked plus a sudo account, exactly like a cloud image.
- Exposure is configuration, never a flag: `Device.FW()` re-reads `/etc/config/firewall` + `/etc/config/upnpd` + `/var/run/miniupnpd.leases` (router) or `/etc/iptables/rules.v4` (host, Fedora/RHEL `/etc/sysconfig/iptables`) on *every* call. Never cache a parsed firewall config, never add a `Device.PortFwd`-style field back, and never seed a redirect for an NPC's convenience: §14 says the attack surface is what the player configured. A config that does not parse yields **no** rules (fail closed) and `uci` refuses to edit a file with parse errors, as real uci does.
- `uci set`/`add`/`delete` only *stage* (`World.UCIStaged`, the pending log is per config so `uci commit <c>` clears exactly its own lines); only `uci commit` writes the file, and `/etc/init.d/firewall reload` is a *check* verb that reports what is in force. If you add a command that changes the packet path, it must go through the same staging, or the two-verb model becomes a lie.
- A forward bypasses the target's LAN-only scope on purpose (that is what publishing a port means), but it does not bypass the target's own rules or the need for a service to be listening. `WPort == 0` on a redirect is a DMZ matching every port. Rendered files are the interface: `iptables` and the packet path both read `/etc/iptables/rules.v4`, and both `:INPUT DROP [0:0]` and `-P INPUT DROP` parse.
- `routerFor(dev) == dev` is not "the gateway": `upnpc` requires a gateway *upstream* of the caller, so it works from a LAN host and prints `no UPnP-enabled gateway on this network` on the router itself — that is correct, not a bug (delete mappings from a client). `upnpd.enabled=0` stops honouring leases without deleting them; `camctl status` reports configuration and reachability separately, because the gap between them is the whole point of a stale exposure.
- Addresses have ONE vocabulary: `core.ClassifyAddr` (`internal/core/addrs.go`) decides public/private/shared/ULA/link-local/loopback and every other subsystem asks it — never re-derive "is this public" from a string prefix. `Kind` has no `virtual` member: a virtual IP is a *secondary address*, not a kind, and lives in `Iface.Extra`.
- `routerFor` skips the device itself (a router is not its own upstream), so any caller that must judge a packet addressed to the household's **edge** has to fall back to `r = dst` when the destination's profile is `router` and `routerFor` returned nil. `Dial`, `Reach` and `ForwardTarget` all do this; a new call site that forgets it silently stops logging and stops following redirects (that bug cost 14 tests once).
- A datacenter profile's power is the customer's to control: `Powered()` returns `d.NetUp` for `core|infra|vps` (the house cannot darken a colo, but the panel can switch a node off — §12 启动/关机). `CutPower`/`RestorePower` still skip datacenters and BMCs; `setPowered` stays unexported and is reached through `World.VPSStart/VPSStop/VPSReboot`.
- A VPS is a `Device`, so a lifecycle verb must change the device, not print: `World.ReinstallVPS` wipes `d.FS`/`d.Users`/`Installed` and re-seeds the image (new password seeded with the rebuild count, so the old one really stops working) while keeping the addresses; `VPSResize`/`VPSAddDisk` require the node stopped, charge the household and move `NodeRecord.Monthly`; `VPSnapshot` copies the disk (a live copy, `cloneVFS`) and `VPSRestore` requires a power-off. Panel records live in `Provider.Nodes` (`NodeRecord`), and `LoadWorld` backfills them for old saves.
- Regions are networks, not labels: `DefaultRegions()` gives each NovaPanel datacenter its own AS (`asNova`/`asNovaUS`/`asNovaAP`), its own /24 in `publicBlocks` and its own /48, so `--region` changes the address, the `whois` answer and the real latency. `NodePriceCents` in core is the single price rule (the shell's `vmCost` delegates to it) — never price a node twice.
- The household's physical layer is state, not scenery: `Device.Uplink`/`UplinkPort` plus `SwitchState.Ports` (`internal/core/link.go`), and **one** wire question — `World.linkUpVia(d, crossUplink)`. Traffic that stays inside a switch's island passes `crossUplink=false`, so a switch whose uplink died isolates the island instead of blacking it out (that is why the cameras keep streaming during an outage while nothing reaches the internet). `Dial`/`Reach` prepend the wiring reason ("Connection timed out (link down: port 6 (printer) on sw-hall is down)") so a dark wire is a diagnosis, not a generic failure. `LinkPath` stops at the switch's uplink — do not assert a longer path.
- A switch's port configuration is **the file** `/etc/config/switch`: `RenderSwitchConf` writes it, `LoadSwitchConfig` re-reads it on every `linkUp` and on every `switchctl` call (the same "config is a file" rule as the firewall), and every mutator (`SetPortAdmin`, `SetPortPoE`, `AttachTo`, `Detach`) re-renders it. Never cache a parsed port table.
- PoE is electricity with a budget: `poePowered` spends `SwitchState.BudgetW` in port order, so a port that does not fit is refused while the ports already up keep their power; `SetPoEExceeded`-style "drop everything" behaviour is wrong; `SetPortAdmin` refuses to cut the uplink port and no-ops on an empty one; `DarkenPoE` runs on a plug pull and when a UPS finally runs flat; `LinkReport` shows a PoE port as link **down** when its device has no power, because a PHY without power has no link.
- `Device.UnavailableReason()` is the single phrasing for "why is this machine not answering" (PoE off on which port / suspended lid / flat battery / unplugged / household supply off). The shell's `Connection to host lost (…)`, the switch table's reason column and the SSH entry's out-of-band fallback all use it — do not write a second phrasing. `Powered()` order is PoE → battery/lid → mains: a laptop on battery is a *running* machine (until the battery is flat), and `SetCharging`/`power plug` are the same state (`MainsDropped` + `Battery.Charging` must move together).
- Physical acts are verbs, not shell state: `power cut|boot|plug|unplug|lid open|closed HOST` (the breaker, the socket, the lid) can be performed from another machine because hands are not shell commands — but a suspended or unpowered machine must not run its own commands (the shell gates on `Powered()` *before* dispatch, so a client can never talk a dead box into work). The SSH entry falls back to the BMC when the player's PC has no power (`cmd/neohome/ssh.go`): a dark house must never be a one-way door.
- Printing is a device: the queue lives in the printer's own FS (`/var/spool/cups/queue`, `tray.log`), a page comes out every other tick, and a held job carries its reason (`out of paper`, `printer is offline`). `VFS.Append` never creates the file (it returns `fs.ErrNotExist`) — create it first, which `tray.log` and `/srv/backups/index.log` both had to learn. `lp` dials `core.PrintPort` before spooling, so a dead port fails with the wiring reason. Household verbs are owner-scoped: `switchFor`/`nasFor` require the same `Device.Owner` (reachability is not authority).
- Adding a household device moves the LAN allocator's *lowest free static*, so tests must derive expectations from the world (`lowestFreeStatic` in `tests/lan_test.go`) instead of pinning an address; `EnsureMCPPlayer` (and any allocator caller) lands on whatever is free, `.2`/`.3`/`.4` are incidental. Laptop and printer exist in the seed (`laptop-alex` = `laptop`, so `power lid … laptop`; the laptop has `dropbear:22` or it cannot be reached at all).
- §17 resources are mostly *derived*: memory in use (`Device.MemUsed`), disk in use (`FS.DiskUsedMB`), the process table and the CPU demand (`CPUDemand`) are read from the real state every time. `Rsrc` (`internal/core/resources.go`) stores only what cannot be derived — load averages, swap, OOM count, fork refusals, dropped log lines, the full-disk latch and the per-tick rates — and is created lazily, so an older save without one never panics. `ResourceTick()` runs last in `World.Tick` and does nothing at all for an unpowered device.
- One CPU fact: `Proc.WantCPU` is what a process asked for, `Proc.CPU` is what it got, and `CPUShare()` is the only multiplier between them. Anything that must slow down under load consults the share instead of inventing a slowdown — the printer's spooler credit (`PrinterState.Credit`, a sheet costs `pageWork`), the assistant's job progress (`Task.Progress`), and `WorkRate()` for bulk work. `WorkRate()` = `min(NetMbps, DiskMBps)/500 × share`, so a gigabit-plus-500 MB/s machine is exactly one unit per tick: that is the invariant every "one phase per tick" system already relied on (mirror sync now spends `Repo.SyncCredit` against it). `DiskMBps` comes from the profile; a test or a seed may override `Resources().DiskMBpsBench` (0 = derive).
- RAM → swap → OOM is the same chain for hosts and guests: over RAM pages into `SwapTotalMB()` (= RAM/2, the rule `free` prints), swap full with the machine still over RAM kills the biggest resident non-builtin process for real (or fails every service when only daemons are left). The *first* OOM counts as an incident (`OOMCount == 0 ||` in `oomKill`) — the tick-zero case used to silently no-op; one incident lasts 3 ticks so a burst is one number.
- Disk fullness is byte-accurate and has exactly one limit: `Device.DiskLimitMB()` — a guest's virtual disk when it is a guest, otherwise `HW.DiskMB` — and `DiskFull()` compares the FS's real bytes against it (the `DiskUsedMB()` rounding means a disk at the limit reads full). The single gate for player writes is `Device.WriteGuest` (`echo >`, `cp`, `mv`, `touch`, FTP uploads and the shell history all go through it) and it really returns `ErrNoSpace`. Logs are the second casualty: `Logf` drops and counts lines while full, and `diskTick` writes the "N message(s) dropped" reckoning once there is room. Installs check room in `InstallFromView` and return a `PackageError`, so each package manager reports it in its own voice; `vmdisk.go`'s `WriteGuest`/`DiskFull` are the §17 ones (guests gained host semantics, not the other way round).
- §33's tools are installed software, never ambient features: `pkgBinaries` in `internal/shell/sec_cmds.go` maps each command to the file its package installs, and `pkgCommandMissing` is what makes a fresh machine answer `command not found`. Their configuration (/etc/fail2ban/jail.conf, /etc/suricata/rules, /etc/aide/aide.conf, /etc/monit/monitrc, /etc/audit/rules.d, /etc/restic/env, /etc/rkhunter.conf) is re-parsed on every call — never cache a parsed jail, rule set or watch list. A ban is enforced in `Dial` before every other gate, and `Device.IsBannedBy(src)` checks both addresses a source is known by (its v6 source address and its v4 `WANIP`), because an operator bans what a log line showed them. A rejection is recorded by the *target* (`NoteAuthFail`), never by the client.
- The IDS reads the flow table; there is no packet capture. Four rule kinds exist in `/etc/suricata/rules` — `portscan ports=`, `authfail fails=`, `flood conns=`, `exploit` — each with `window=`, `action=ban,alert`, `level=` and `bantime=`. Adding a kind means adding a shape in `idsTick`; do not invent a fifth sensor.
- `restic`'s repository is real files (config, keys/, data/<xx>/<blob>, snapshots/<id>, index/) and content-addressed: the blob name is its hash, so a blob that is already there is not rewritten and `check` can verify every reference. One blob per file, capped at 1 MiB (`resticBlobLimit`) — a stated model limit. Every write to a repository goes through `ResticRepo.{mkdir,put}` (gated by `MkdirAllChecked`/`WriteGuest`), so a repository on a NAS really fails when the NAS is down or its disk is full. Both readers re-hash what they read against the blob's own name: `ResticCheck` reports `blob <id> is corrupt: hashes to <id> (snapshot …, path)`, and `ResticRestore` refuses those bytes by name instead of writing them into the live tree — corruption is a fact the tool states, never a silent restore of the wrong bytes. `/etc/cron.d` is read by the game's cron (`ParseSystemCrontab` + `Device.CronDotFiles`): five fields, then the user, then the command; a filename containing a dot is skipped, as Vixie cron skips it.
- The shell's text handling is load-bearing for §33: `tokenize` follows the real quote rules (single quotes are literal, backslash included; inside double quotes only `$`, `` ` ``, `"`, `\` and newline lose theirs), `printf` really formats and repeats its format, and `echo -e` is the only echo that interprets escapes. Configuration files in this world are written with `printf '...\n...' > file`, so breaking any of those three breaks the story rather than a formatting nicety.
- Model limits, stated as such rather than dressed up as errnos: `dd` refuses a single file over 64 MiB (`maxFileMB`) because this world's files hold real bytes in memory — a disk still fills the honest way, with several files; `stress` runs as a *background* load (there is no job control to wait on) with `--timeout` ticks or `pkill stress` to end it; the process limit is `RAMMB/8` (min 24) and refusals are counted into `Rsrc.ForksRefused`. `vmstat` prints one sample per command — the world clock only moves on ticks, so there is nothing to sleep for.
- §34's desks answer for addresses, they do not know people: a desk's findings come only from the hosts inside its own AS (`deskFindings`), a report is refused unless the reporter's own records hold the address, and the console is a Unix group on the organisation's own machine (`OnDeskStaff`, called with the *device you are logged into*) — never a role flag or a remote admin socket. `whois`/RDAP stops at network + abuse contact, `DeskFor` routes a CGNAT address to the provider that runs the pool, and `ReportAbuse` records `rep.Owner` as the reporter (the ssh actor goes in the history).
- §35's unit is walked by `LawTick`, not by the network ladder: `advanceCase` returns early for `DeskLaw` files so a lawful request is never answered by enforcement. Every rung is paid for out of the unit's own hours ledger (`lawSpend`; a short ledger pushes `Due` 30 sim-minutes and writes a line, it never sleeps), and `namedSubscriber` is the single rule for "a network disclosed a person": `subscriberRecord` returning `unassigned (<host>)` is a rack, not a subscriber, and yields no order. The registry is refused as a target — it publishes allocations and is not the network to ask. The unit's powers are the `lawDeskAct` switch; adding `suspend`/`refer`/`notify` there would break §35's promise that it acts on records, not on lines.
- `mail send` must leave from the machine the session is on (`World.SendMailFrom(s.Dev, …)`, used by `cmdMail`): the same account name (`contractor`) exists on several organisations' desks, and `MailSourceFor` picks the first, which would put a stranger's hostname on the From line of a complaint. A mailbox file is an mbox — the header is `From <addr> <stamp>` and body lines are escaped `>From ` — so a parser reads that, not `From:` (`inboxMessages` learned this).
- §36's intrusions are state, not events: a credential that works for the *world's own attacker* (`src.ID == ScannerID`) plants a `Foothold` (`internal/core/intrusion.go`) with three artifacts — a `Proc`, a payload under `/tmp`, a line in `/etc/cron.d` — and the line is the persistence: the tick restarts the process while it is there and ends the presence when it is gone. `IntrusionTick` runs after `ScannerTick` in `World.Tick`. Whether anyone notices comes from the target's own §33 services (auditd/aide/rkhunter/suricata), never from a scripted alert; `secstat compromise [clean]` is the only reader/writer, and a NATed household box is not in `ScannableTargets`, so it can only be owned through a forward the player published.
- rDNS is published per address: `answerVia` hands `.in-addr.arpa`/`.ip6.arpa` queries to `ptrAnswer`, which answers with the node's `RDNS` only for a block whose AS publishes a reverse zone (`AS.RDNS`); private, CGNAT and ULA addresses deliberately have no PTR. A lookup must never name a person (§13).
